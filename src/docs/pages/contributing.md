## 问题反馈

项目的统一反馈入口是 [logdog-tech/logdog](https://github.com/logdog-tech/logdog)。请先搜索已有问题；如果没有相同报告，再新建 issue。

有效的问题报告应包含可重复的操作路径，并清楚区分预期结果与实际结果。截图能够补充说明，但不应替代文字步骤。

## 复现信息模板

```text
环境：操作系统 / 浏览器及版本
版本：站点地址 / Git 提交号
数据：格式 / 文件大小 / 行数（如已知）
操作：
1. 打开文件……
2. 搜索……
3. 点击……
预期结果：
实际结果：
附件：脱敏样例、截图或控制台错误
```

提供样例前，请移除令牌、个人信息和内部地址。可以生成保留相同格式、行长和数量的人工日志，无需上传真实业务日志。

## 参与代码改进

从当前代码建立开发分支，尽量让一次修改围绕一个明确问题。涉及行为变化时，应说明原有行为、新行为及验证方法。

```bash
npm run type-check
npm run test:unit
npm run build
```

构建会生成 WASM 产物。检查差异时，区分有意修改与工具链引起的二进制变化，不要把无关产物混入提交。

## 完善文档

文档内容在 `src/docs/pages/` 中，以 Markdown 编写。侧栏顺序和页面描述在 `src/docs/content.ts` 中维护。修改功能时，也请同步更新对应指南和示例。

文档应描述已经可用的行为，不把计划中的能力写成现有功能。发布前检查内部链接、示例命令、搜索结果和移动端阅读布局。
